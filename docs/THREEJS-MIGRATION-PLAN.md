# DARK ARENA — технический план перехода на Three.js

Версия плана: 1 · 9 ноября 2026 · Статус: **на согласовании**. Код по этому плану ещё не писался.

## 0. Цели и ограничения (из решений владельца)

- Сохранить игровой интерфейс (меню, HUD, настройки, пауза, экран смерти).
- Сохранить и улучшить управление (ПК + iPhone, всё, что исправлено в BUILD 1.3).
- Не потерять игровую логику (волны, спавн, урон, патроны, перезарядка, коллизии).
- Работа на GitHub Pages как статические файлы, без сервера.
- Первый 3D-прототип — на существующей карте 16×16 и отдельно от рабочей игры.
- Расширяемость: новые карты, оружие и противники — данными, а не переписыванием кода.
- Готовность к кооперативу в будущем, но без сетевого кода сейчас.

## 1. Сравнение вариантов архитектуры поставки

| | **A1. Один HTML + CDN** | **A2. ES-модули без сборки, Three.js в репозитории** | **A3. Vite + TypeScript + сборка в GitHub Actions** |
|---|---|---|---|
| Как устроено | Как сейчас: один файл, `<script type="module">`, Three.js с jsDelivr через `importmap` | Папка с модулями (`src/*.js`), `importmap` указывает на `vendor/three/` внутри репозитория | Исходники на TS, сборка Vite, Actions публикует `dist/` на Pages |
| Сборщик | нет | нет | да (Node, npm, CI) |
| Надёжность загрузки | зависит от CDN | всё с GitHub Pages, версия закреплена файлом | всё с Pages, бандл минифицирован |
| Организация кода | файл быстро станет >3000 строк | модули по слоям, читаемо | лучшая (типы, проверки) |
| Порог входа для владельца | минимальный | низкий: правка файла → push → готово | выше: локальная сборка, CI, `node_modules` |
| Отладка в браузере | просто | просто (исходники как есть) | через source maps |
| Размер загрузки | three ≈ 170 КБ gzip + игра | то же (+ можно взять только нужные addons) | меньше за счёт tree-shaking (~120–150 КБ) |
| Путь развития | тупиковый при росте | **код совместим с Vite: переход на A3 позже — без переписывания** | сразу «взрослый» |
| Риск сейчас | средний (монолит) | **низкий** | средний (инфраструктура раньше игры) |

**Рекомендация: A2.** Модули без сборки, Three.js r186 (`three@0.186.0`, на него рассчитаны установленные Skills)
лежит в `vendor/three/` с указанием версии и лицензии MIT. Если проект вырастет (TypeScript, много ассетов,
сжатие моделей), переходим на A3 без переписывания: ES-модули Vite принимает как есть.

## 2. Архитектура игры (слои)

```
index.html (DOM: меню, HUD, настройки — перенос из BUILD 1.3)
 └─ src/main.js — цикл: input → sim (фиксированный шаг 60 Гц) → render (интерполяция) → ui/audio
     ├─ input/   DOM-управление из 1.3 (джойстик, обзор, кнопки, редактор HUD) + Pointer Lock мышь на ПК
     │           → выдаёт InputState { move{x,y}, look{dYaw,dPitch}, fire, jump, reload }
     ├─ sim/     ЧИСТАЯ ЛОГИКА без DOM и без Three.js: мир-сетка, игрок, враги, оружие, волны, коллизии,
     │           попадания. Детерминированный шаг, состояние сериализуемо → основа кооператива
     │           → выдаёт события: shot, hit, kill, playerDamaged, waveStart, waveCleared, reload…
     ├─ render/  Three.js: строит сцену из карты, читает состояние sim, рисует (стены, враги, оружие, эффекты)
     ├─ ui/      HUD и меню из 1.3, обновляются по событиям sim
     ├─ audio/   Web Audio: позиционные звуки по событиям sim (файлы звуков — свои, без генераторов)
     └─ data/    карты (JSON), типы врагов, оружие, волны — всё расширяется данными
```

Ключевое правило: **sim не знает о Three.js**. Это даёт:
- перенос логики 1.3 почти 1:1 и её тестирование в Node без браузера;
- возможность позже запустить ту же sim на сервере для кооператива;
- замену или улучшение рендера без риска сломать геймплей.

## 3. Что и как переносится из BUILD 1.3

| Часть 1.3 | Куда | Как |
|---|---|---|
| Меню, HUD, настройки, пауза, смерть, редактор кнопок (HTML/CSS) | `index.html`, `ui/` | перенос без изменений вида; логика показа экранов — в `ui/screens.js` |
| Сенсорное управление, защита от зума, `releaseAll` | `input/touch.js` | перенос; дальше — мёртвая зона, чувствительность «° на ширину экрана», safe area (Skill `dark-arena-mobile`) |
| Клавиатура | `input/keyboard.js` | перенос + **мышь через Pointer Lock** (сейчас мыши нет) |
| Настройки (`darkarena_settings_v10`) | `ui/settings.js` | тот же ключ + миграция на v11 при изменении схемы — настройки игроков сохраняются |
| `MAP`, `wall`, `canStand`, `moveEntity` | `sim/world.js`, `sim/collision.js` | перенос 1:1, покрыть тестами |
| Волны, спавн, урон, патроны, перезарядка | `sim/waves.js`, `sim/weapon.js` | перенос 1:1, параметры → `data/` |
| Попадание (угловой допуск) | `sim/hitscan.js` | заменить на луч против хитбоксов врага (голова/тело) — аналитически, без Three.js |
| Отрисовка рейкастером, `drawZombie`, `drawGun` | `render/` | **переписывается** на Three.js |
| Мини-карта | `ui/minimap.js` | перенос (Canvas 2D поверх WebGL) |

Система координат: клетка карты (x, y) → мир Three.js (x·S, 0, y·S), где S — размер клетки
(предложение: S = 2 м, высота стен 3 м, глаза 1,6 м). Внутри sim единицы остаются «клетками»,
как сейчас, поэтому скорости и баланс 1.3 сохраняются. Угол `yaw` sim → поворот камеры вокруг оси Y.

## 4. Рендер и визуальный стиль

- Стены: `InstancedMesh` из сетки — 1–3 вызова отрисовки на всю арену.
- Ретро-конвейер: рендер в низкое разрешение (`WebGLRenderTarget`, ~1/3 экрана, `NearestFilter`) с
  растягиванием на экран — пиксельный вид, заодно в разы дешевле для телефона. Настройка «разрешение рендера».
- Пиксельные текстуры генерируем кодом (canvas) на первых этапах — без внешних ассетов.
- Освещение: туман, тусклый ambient/hemisphere, несколько точечных источников (лампы, вспышка выстрела),
  тени — только на «Высоком» качестве. Пресеты качества Низкое / Среднее / Высокое, автоподбор по FPS.
- Враги: сначала низкополигональные «блочные» модели из примитивов с процедурной анимацией (ходьба, удар,
  отброс при попадании, падение); затем — glTF со скелетной анимацией.
- Оружие: отдельная сцена/камера поверх мира (не проваливается в стены), отдача, покачивание, вспышка.
- Эффекты: частицы попаданий (пул объектов), декали, вспышка урона, тряска камеры (с ограничением для доступности).

Бюджеты на iPhone 12-класса: ≤ 60 draw calls, ≤ 100k треугольников, pixelRatio ≤ 1,5 (по умолчанию рендер
в пониженном разрешении), без аллокаций в горячем цикле, цель 60 FPS, минимум 30 FPS.
Обработка `webglcontextlost/restored` обязательна (iOS при нехватке памяти).

## 5. Расширяемость (данные)

```
data/maps/training.json   { "grid": [...строки как сейчас...], "legend": {"1":"wall_concrete","2":"wall_red","3":"wall_green"},
                            "playerStart": [8,8], "spawns": [...], "lights": [...], "props": [...] }
data/enemies.json         { "infected": { "hp": 2, "speed": 0.65, "speedPerWave": 0.09, "damage": 9, "attackCooldown": 1.0, "hitboxes": {...} } }
data/weapons.json         { "rifle": { "fireInterval": 0.135, "damage": 1, "mag": 30, "reserve": 120, "reload": 1.3, "spread": ..., "recoil": ... } }
data/waves.json           правила роста волн (сейчас: 5 + 2·(волна−1), максимум 23)
```
Новая карта, оружие или враг — это новая запись в данных и, при необходимости, новая модель.
Сетка остаётся форматом первых карт; высоты, лестницы и неровный рельеф добавляются позже
(коллизии против мешей через BVH — только когда это понадобится картам).

## 6. Тестирование

- `tests/sim/*.test.js` — логика в Node без браузера: движение, коллизии, волны, попадания, детерминизм.
- `tests/e2e/*.test.js` — Playwright: меню, мультитач, защита от зума, освобождение пальцев (перенос тестов 1.3),
  скриншоты, замер FPS/времени кадра с замедлением CPU.
- Хук `window.__DA` только с `?debug=1`.
- Сравнение «до/после»: те же сценарии движения и стрельбы дают те же числа в 1.3 и в прототипе.
- Ручной чек-лист на iPhone — обязателен для каждого этапа.

## 7. Готовность к кооперативу (закладываем, не реализуем)

Фиксированный шаг sim, ввод в виде команд `{tick, move, look, fire…}`, у сущностей стабильные `id`,
состояние сериализуется в снапшот, случайность — через seed. Тогда позже можно выбрать модель
(авторитетный сервер на той же sim: Node/Cloudflare Durable Objects и т. п.) — это отдельное
архитектурное решение со своей оценкой инфраструктуры.

## 8. Этапы

Каждый этап — отдельная ветка/PR, отчёт и ваше подтверждение. Рабочая игра не трогается до этапа M5.

| Этап | Что делаем | Критерии готовности |
|---|---|---|
| **M0. Скелет прототипа** | `prototype-3d/`: `index.html`, `importmap`, `vendor/three` r186, пустая сцена, цикл, пресеты качества | открывается с GitHub Pages на ПК и iPhone; нет ошибок; FPS-счётчик |
| **M1. Карта и движение** | sim (перенос коллизий и движения 1.3 + тесты), стены из сетки, пол/потолок, туман; управление 1.3 + Pointer Lock | ходьба по той же карте ощущается как в 1.3; все тесты движения/коллизий проходят; ≥ 30 FPS на iPhone (цель 60) |
| **M2. Геймплей-паритет** | враги (блочные модели), волны, стрельба лучом по хитбоксам, урон, патроны, HUD и меню из 1.3 | полный цикл «старт → волны → смерть → рестарт» как в 1.3; e2e-тесты 1.3 адаптированы и проходят |
| **M3. Ощущения и вид** | ретро-конвейер, свет, оружие от первого лица, отдача, частицы, реакция врагов на попадания, звук | ваша оценка на ПК и iPhone; бюджеты производительности соблюдены |
| **M4. ИИ и баланс** | A* по сетке, разведение врагов, 2–3 типа заражённых, кривая сложности | враги не застревают; волны растут по таблице данных |
| **M5. Замена production** | прототип становится основной игрой; 1.3 остаётся доступной по ссылке | ваше подтверждение; тег отката |

Оценка объёма: M0–M2 — основная техническая работа миграции, M3–M4 — качество игры.
Сроки зависят от числа итераций проверки на iPhone.

## 9. Риски и как их снижаем

| Риск | Мера |
|---|---|
| Производительность WebGL на старых iPhone | рендер в пониженном разрешении, пресеты, замеры на каждом этапе |
| Потеря WebGL-контекста на iOS | обработка `webglcontextlost`, пересоздание ресурсов |
| «Ощущения» изменятся | sim переносится 1:1, параметры в данных, сравнение с 1.3 бок о бок |
| Разрастание объёма | этапы с критериями, ничего сверх утверждённого этапа |
| Зависимость от внешних CDN | Three.js хранится в репозитории |
| Размер загрузки | только нужные addons; модели и текстуры — с бюджетом |
